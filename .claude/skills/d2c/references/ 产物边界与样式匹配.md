# D2C 产物边界与样式匹配

维护 `d2c-extract`、`d2c-generate`、`d2c-merge` 和 `d2c-verify` 之间的交接时，使用这份参考。

## 基础概念

### 样式属性

样式属性是浏览器最终识别的 CSS 属性，例如 `background-color`、`border-radius`、`font-size`、`padding`。

在 D2C 产物中，样式属性通常对应 `property` 或 `requiredStyle` 中的字段，例如：

```json
{
  "property": "backgroundColor",
  "rawValue": "#1677ff"
}
```

它回答的是：要设置哪个视觉属性。

### Raw Value

Raw value 是从 Figma 直接读取到的原始样式值，例如 `#1677ff`、`6px`、`14px`。

Raw value 是视觉还原的基准。preview 阶段默认优先使用 raw value，避免项目 token 映射不准导致视觉失真。

### Token

Token 是设计系统里的语义化设计值，用来表达某个 raw value 在设计体系里的含义。例如 `#1677ff` 可能对应 `color-primary`，表示主色。

Token 不是浏览器原生概念，也不等于 CSS 变量或 Less 变量。它回答的是：这个值在设计系统里代表什么。

在 D2C 中，`tokenCandidates` 只表示 raw value 的语义候选，不代表最终项目 token 映射。

### CSS 变量和项目表达

CSS 变量是 CSS 原生变量机制，例如 `var(--color-primary)`。项目表达还可能是 Less 变量、Sass 变量、Tailwind class、theme 字段、mixin 或组件 props。

同一个 token 可以在不同项目里落成不同表达：

```css
background-color: var(--color-primary);
```

```less
background-color: @primary-color;
```

```tsx
<Button type="primary" />
```

因此，`color-primary` 不能直接等同于 `@primary-color` 或 `var(--color-primary)`。更准确的关系是：

```text
样式属性：backgroundColor
Raw value：#1677ff
Token 候选：color-primary
项目候选表达：@primary-color / var(--color-primary) / theme.colors.primary
最终采用结果：resolvedTokens 或 fallback raw value
```

## 边界

`d2c-extract` 记录设计事实和候选项：

- `requiredStyle`：从 Figma 读取的视觉要求
- `tokenCandidates`：可能的语义 token 含义
- `uiPatternCandidates`：通用 UI 角色和组合模式

`d2c-generate` 创建预览决策：

- `tokenHints`：供后续项目适配使用的语义 token 提示
- `componentMappings`：选定组件、导入路径、props 和决策依据
- `styleFit`：选定组件覆盖所需视觉样式程度的静态估算
- 预览样式默认使用原始 Figma 值，使视觉还原独立于目标项目 token 的可用性

`d2c-merge` 解析项目决策：

- `resolvedTokens`：选定的项目 token、工具类、CSS 变量、mixin、局部变量，或兜底原始值
- 业务组件适配：目标导入、数据契约、CSS Modules 和项目编码规则

`d2c-validate` 运行两次：

- 预览校验在视觉迭代前检查生成的预览项目
- 目标校验在导入、token、资源和业务组件完成适配后检查合并后的目标项目

`d2c-verify` 运行两次：

- 预览验证在 merge 前检查基于原始值的视觉还原
- 目标验证检查实际合并后的页面，并作为最终视觉证据

## Extract 示例

Figma 按钮事实：

```json
{
  "components": [
    {
      "nodeId": "12:34",
      "name": "SubmitAction",
      "role": "button",
      "requiredStyle": {
        "width": 96,
        "height": 32,
        "backgroundColor": "#1677ff",
        "borderRadius": 6,
        "fontSize": 14,
        "fontWeight": 400,
        "paddingX": 16,
        "paddingY": 4
      }
    }
  ],
  "tokenCandidates": [
    {
      "nodeId": "12:34",
      "property": "backgroundColor",
      "rawValue": "#1677ff",
      "candidates": [
        {
          "semantic": "color-primary",
          "confidence": 0.92,
          "evidence": ["匹配主操作填充色"]
        },
        {
          "semantic": "color-brand",
          "confidence": 0.74,
          "evidence": ["接近品牌蓝"]
        }
      ]
    }
  ],
  "uiPatternCandidates": [
    {
      "nodeIds": ["12:34"],
      "kind": "role",
      "role": "button",
      "pattern": "primary-action",
      "text": "提交",
      "confidence": 0.86,
      "evidence": ["矩形填充", "文本居中", "动作命名"]
    }
  ]
}
```

字段含义：

- `components`：从设计稿中识别出的可生成 UI 节点列表。
- `components[].nodeId`：Figma 节点 ID，用于关联样式、token 候选、UI 模式和后续生成决策。
- `components[].name`：节点或组件的建议名称，可由 Figma 节点名、文本内容或语义角色推断。
- `components[].role`：节点的基础语义角色，例如按钮、输入框、卡片、列表项等。
- `components[].requiredStyle`：从 Figma 读取的视觉还原目标，是 preview 阶段优先使用的样式事实。
- `requiredStyle.width` / `height`：节点尺寸，单位为 px。
- `requiredStyle.backgroundColor`：节点背景色原始值。
- `requiredStyle.borderRadius`：节点圆角原始值，单位为 px。
- `requiredStyle.fontSize` / `fontWeight`：文本字号和字重。
- `requiredStyle.paddingX` / `paddingY`：水平和垂直内边距，单位为 px。
- `tokenCandidates`：基于 raw value 推断出的设计语义 token 候选，不代表最终项目 token 映射。
- `tokenCandidates[].nodeId`：该 token 候选关联的 Figma 节点 ID。
- `tokenCandidates[].property`：候选对应的样式属性，例如 `backgroundColor`、`color`、`borderRadius`、`fontSize`。
- `tokenCandidates[].rawValue`：Figma 中读取到的原始样式值，preview 代码应优先使用它保证视觉还原。
- `tokenCandidates[].candidates`：该 raw value 可能对应的语义 token 列表。
- `candidates[].semantic`：项目无关的设计语义，例如 `color-primary`、`color-brand`。
- `candidates[].confidence`：语义判断置信度，取值范围为 0 到 1。
- `candidates[].evidence`：判断依据，用于生成日志、人工复核和后续映射排错。
- `uiPatternCandidates`：基于结构、样式和文案推断出的通用 UI 模式候选。
- `uiPatternCandidates[].nodeIds`：组成该 UI 模式的一个或多个 Figma 节点 ID。
- `uiPatternCandidates[].kind`：候选来源类型，例如语义角色、布局结构或组件组合模式。
- `uiPatternCandidates[].role`：候选的 UI 角色。
- `uiPatternCandidates[].pattern`：更具体的 UI 模式，例如 `primary-action`。
- `uiPatternCandidates[].text`：节点中的主要文本内容。
- `uiPatternCandidates[].confidence`：模式识别置信度，取值范围为 0 到 1。
- `uiPatternCandidates[].evidence`：模式识别依据。

## Context 示例

组件库条目可以暴露样式契约，用于静态匹配：

```json
{
  "components": [
    {
      "name": "Button",
      "importFrom": "antd",
      "matchRoles": ["button", "primary-action"],
      "propsByRole": {
        "primary-action": {
          "type": "primary",
          "size": "middle"
        }
      },
      "styleContract": {
        "height": 32,
        "backgroundToken": "color-primary",
        "borderRadiusToken": "border-radius-base",
        "fontSize": 14,
        "paddingX": 16,
        "supportsIcon": true
      },
      "overridePolicy": {
        "className": true,
        "style": false,
        "tokenOverride": true
      }
    }
  ],
  "matchingRules": {
    "preferLibraryComponentWhenConfidenceAbove": 0.8,
    "styleFit": {
      "useComponent": 0.85,
      "useComponentWithOverrides": 0.65
    }
  }
}
```

字段含义：

- `components`：目标项目或组件库中可复用组件的候选列表。
- `components[].name`：组件名称，用于写入 `componentMappings[].component`。
- `components[].importFrom`：组件导入来源，例如包名、别名路径或项目内路径。
- `components[].matchRoles`：该组件可承接的 UI 角色或模式。
- `components[].propsByRole`：不同角色或模式下推荐使用的 props。
- `styleContract`：组件默认样式能力描述，用于和 `requiredStyle` 计算 `styleFit`。
- `styleContract.height`：组件默认高度。
- `styleContract.backgroundToken`：组件默认背景对应的设计语义 token。
- `styleContract.borderRadiusToken`：组件默认圆角对应的设计语义 token。
- `styleContract.fontSize`：组件默认字号。
- `styleContract.paddingX`：组件默认水平内边距。
- `styleContract.supportsIcon`：组件是否原生支持图标插槽或图标 props。
- `overridePolicy`：生成阶段允许对组件做的样式修正方式。
- `overridePolicy.className`：是否允许通过 className 或 class 做局部覆盖。
- `overridePolicy.style`：是否允许内联 style 覆盖。
- `overridePolicy.tokenOverride`：是否允许通过项目 token 或主题变量覆盖。
- `matchingRules.preferLibraryComponentWhenConfidenceAbove`：UI 模式置信度达到该阈值时，优先考虑复用组件库组件。
- `matchingRules.styleFit.useComponent`：达到该分数时直接使用组件，并仅做少量修正。
- `matchingRules.styleFit.useComponentWithOverrides`：达到该分数时仍可使用组件，但需要记录并生成局部覆盖。

## Generate 示例

React + Ant Design + Less 上下文：

```json
{
  "framework": "react",
  "componentLibrary": "antd",
  "cssStrategy": "less",
  "tokenResolutionRules": [
    {
      "semantic": "color-primary",
      "propertyTypes": ["backgroundColor", "borderColor"],
      "targets": [
        {
          "target": "@primary-color",
          "strategy": "less-token",
          "source": "theme variables",
          "currentValue": "#1677ff",
          "matchType": "value-and-name",
          "confidence": 0.93,
          "evidence": ["token name matches primary", "current value equals rawValue"]
        }
      ]
    }
  ]
}
```

字段含义：

- `framework`：preview 代码生成目标框架。
- `componentLibrary`：当前项目优先适配的 UI 组件库。
- `cssStrategy`：样式输出策略，例如 Less、CSS Modules、Scoped CSS。
- `tokenResolutionRules`：项目上下文提供的 token 候选解析规则，不代表最终采用。
- `tokenResolutionRules[].semantic`：设计语义 token，例如 `color-primary`。
- `tokenResolutionRules[].propertyTypes`：该规则适用的样式属性类型。
- `targets[].target`：候选目标表达，例如 Less 变量、CSS 变量、工具类或 mixin。
- `targets[].strategy`：候选目标的表达策略。
- `targets[].source`：候选目标来源，例如主题变量文件、设计系统配置或人工适配器。
- `targets[].currentValue`：候选目标当前解析出的实际值，用于和 Figma `rawValue` 比对。
- `targets[].matchType`：匹配方式，例如 `value-and-name`、`value-only`、`name-only`、`near-value`、`manual`。
- `targets[].confidence`：项目 token 候选解析置信度，不代表最终采用。
- `targets[].evidence`：解析依据，用于 merge 决策和人工复核。

生成决策：

```json
{
  "tokenHints": [
    {
      "nodeId": "12:34",
      "property": "backgroundColor",
      "rawValue": "#1677ff",
      "previewValue": "#1677ff",
      "semanticCandidates": [
        {
          "semantic": "color-primary",
          "target": "@primary-color",
          "strategy": "less-token",
          "source": "theme variables",
          "currentValue": "#1677ff",
          "matchType": "value-and-name",
          "confidence": 0.93,
          "status": "candidate",
          "evidence": ["token name matches primary", "current value equals rawValue"]
        }
      ],
      "status": "candidate"
    }
  ],
  "componentMappings": [
    {
      "nodeId": "12:34",
      "component": "Button",
      "importFrom": "antd",
      "props": {
        "type": "primary",
        "size": "middle"
      },
      "styleFit": {
        "score": 0.91,
        "covered": ["height", "backgroundColor", "fontSize", "padding"],
        "needsOverride": ["borderRadius"],
        "decision": "use-component-with-class"
      }
    }
  ]
}
```

字段含义：

- `tokenHints`：由 `tokenCandidates` 结合项目上下文转换出的 token 提示，供 merge 阶段继续解析。
- `tokenHints[].nodeId`：该提示关联的 Figma 节点 ID。
- `tokenHints[].property`：提示对应的样式属性。
- `tokenHints[].rawValue`：Figma 原始值。
- `tokenHints[].previewValue`：preview 阶段实际使用的值，默认等于 `rawValue`。
- `tokenHints[].semanticCandidates`：可用于目标项目适配的语义 token 候选。
- `semanticCandidates[].semantic`：项目无关的设计语义。
- `semanticCandidates[].target`：当前项目上下文中匹配到的 token、变量、工具类或 mixin。
- `semanticCandidates[].strategy`：目标表达方式，例如 `less-token`、`css-variable`、`tailwind-class`。
- `semanticCandidates[].source`：候选目标来源。
- `semanticCandidates[].currentValue`：候选目标当前解析出的实际值。
- `semanticCandidates[].matchType`：匹配方式，例如名称匹配、值匹配、近似值匹配或人工规则。
- `semanticCandidates[].confidence`：继承或修正后的匹配置信度。
- `semanticCandidates[].status`：候选状态，generate 阶段默认保持 `candidate`。
- `semanticCandidates[].evidence`：候选解析证据。
- `tokenHints[].status`：提示状态，例如 `candidate`、`raw-only`、`pending-project-adapter`；`confirmed` 只应由 merge 阶段写入。
- `tokenResolutionRules` 和 `tokenHints` 不改变 preview 样式输出；`previewValue` 默认仍使用 `rawValue`。
- `componentMappings`：设计节点到实际代码组件的选择结果。
- `componentMappings[].nodeId`：被映射的 Figma 节点 ID。
- `componentMappings[].component`：选定的组件名称。
- `componentMappings[].importFrom`：组件导入来源。
- `componentMappings[].props`：根据 UI 模式和组件库规则推导出的 props。
- `componentMappings[].styleFit`：选定组件对 `requiredStyle` 的静态覆盖评估。
- `styleFit.score`：样式匹配分数，取值范围为 0 到 1。
- `styleFit.covered`：组件默认样式已覆盖的视觉属性。
- `styleFit.needsOverride`：需要额外 class、token 或局部样式覆盖的视觉属性。
- `styleFit.decision`：生成阶段的组件使用决策。

生成的 React 代码：

```tsx
import { Button } from 'antd'

export function SubmitAction() {
  return <Button type="primary">提交</Button>
}
```

生成的预览样式在需要局部覆盖时保留原始值：

```css
.submitAction {
  background: #1677ff;
  border-radius: 6px;
  padding: 4px 16px;
}
```

Vue + Element Plus 上下文可以用不同方式解析同一个 extract 产物：

```json
{
  "componentMappings": [
    {
      "nodeId": "12:34",
      "component": "ElButton",
      "importFrom": "element-plus",
      "props": {
        "type": "primary"
      }
    }
  ],
  "tokenHints": [
    {
      "nodeId": "12:34",
      "property": "backgroundColor",
      "rawValue": "#1677ff",
      "previewValue": "#1677ff",
      "semanticCandidates": [
        {
          "semantic": "color-primary",
          "target": "var(--el-color-primary)",
          "strategy": "css-variable",
          "source": "element-plus theme",
          "currentValue": "#1677ff",
          "matchType": "value-and-name",
          "confidence": 0.91,
          "status": "candidate"
        }

```

字段含义：

- `componentMappings`：Vue 场景下的组件选择结果，字段含义与 React 示例一致。
- `tokenHints`：同一个 extract 产物在不同项目上下文下可以解析成不同目标表达。
- `semanticCandidates[].target`：示例中表示 `color-primary` 在 Element Plus 上下文中存在一个 CSS 变量候选。
- `semanticCandidates[].strategy`：示例中使用 `css-variable` 表示通过 CSS 变量表达 token。

```vue
<template>
  <el-button type="primary">提交</el-button>
</template>
```

## Merge 示例

Merge 会根据 `tokenHints`、目标项目上下文和现有业务样式，解析最终项目 token 表达式：

```json
{
  "resolvedTokens": [
    {
      "nodeId": "12:34",
      "property": "backgroundColor",
      "rawValue": "#1677ff",
      "semantic": "color-primary",
      "target": "@primary-color",
      "strategy": "less-token",
      "source": "theme variables",
      "currentValue": "#1677ff",
      "matchType": "value-and-name",
      "confidence": 0.93,
      "usage": "src/components/SubmitAction/index.less",
      "status": "resolved"
    }
  ]
}
```

字段含义：

- `resolvedTokens`：merge 阶段最终选定并落入目标项目代码的 token 解析结果。
- `resolvedTokens[].nodeId`：该解析结果关联的 Figma 节点 ID。
- `resolvedTokens[].property`：被解析的样式属性。
- `resolvedTokens[].rawValue`：原始 Figma 值，用作兜底和审计依据。
- `resolvedTokens[].semantic`：最终采用的设计语义。
- `resolvedTokens[].target`：目标项目中的最终表达，例如 Less 变量、CSS 变量、工具类、mixin 或局部变量。
- `resolvedTokens[].strategy`：最终表达策略。
- `resolvedTokens[].source`：最终表达来源。
- `resolvedTokens[].currentValue`：最终表达当前解析出的实际值；用于判断是否会改变视觉结果。
- `resolvedTokens[].matchType`：最终采用时的匹配方式。
- `resolvedTokens[].confidence`：最终解析置信度。
- `resolvedTokens[].usage`：该 token 解析结果实际写入或影响的目标文件。
- `resolvedTokens[].status`：解析状态，例如 `resolved`、`fallback-raw`、`manual-review`。

候选不可靠时，merge 应保留 raw value：

```json
{
  "resolvedTokens": [
    {
      "nodeId": "12:34",
      "property": "backgroundColor",
      "rawValue": "#1677ff",
      "semantic": "color-primary",
      "target": null,
      "strategy": "raw-value",
      "source": "preview raw value",
      "currentValue": "#1677ff",
      "matchType": "none",
      "confidence": 0,
      "usage": "src/components/SubmitAction/index.less",
      "status": "fallback-raw",
      "fallbackReason": "project token value differs from design rawValue"
    }
  ]
}
```

合并后的样式：

```less
.submitAction {
  background: @primary-color;
  border-radius: @border-radius-base;
  padding: 4px 16px;
}
```

## Style Fit 规则

使用 `requiredStyle` 作为目标，并与组件样式契约进行比较：

- `score >= 0.85`：使用组件，并添加小幅 class 调整
- `0.65 <= score < 0.85`：使用组件，并添加局部样式覆盖
- `score < 0.65`：生成原生标记或新组件

`styleFit` 是静态估算。`d2c-verify` 是最终视觉关口，因为组件库默认样式、运行时 CSS 优先级、字体加载和浏览器渲染都会改变实际结果。
