# 轻量 D2C Skill 方案设计（历史摘要）

> 日期：2026-09-09
> 状态：已实施，当前规则以 `.claude/skills/` 和现行文档为准。

## 背景

早期方案包含执行内核、状态机、标准化设计文件、恢复机制和阶段报告。最终决定改为轻量 Skill：由模型在当前会话中读取证据、展示方案、等待确认、修改代码并验证。

## 关键决策

- 日常能力收敛为一个通用 `d2c` Skill；Benchmark 独立存在。
- 主 Skill 保存固定流程和停止条件，条件性细节放入一层 Reference。
- 项目规则由目标项目根目录的 `D2C.md` 保存，不内置特定项目模板。
- 支持官方 Figma MCP 与 Figma-Context-MCP；默认官方，只在约定的 OAuth 授权失败范围内切换。
- 写业务代码前，先分析 Figma、项目组件和 Token，并展示 ASCII 结构与实现预览。
- 工程验证和视觉复核必须落在目标项目真实页面；Chrome 仅用于定位已经确认的视觉偏差。
- Subagent 只做有界只读分析，主模型负责决策和写入。

## Benchmark

- 一次生成 PC 数据、PC 图表、移动内容和移动表单四个固定场景。
- PC 使用 React、Ant Design 和 ECharts；移动端使用 Vue 3 和 Vant。
- Figma 原稿与真实页面并排展示，不评分、不排名、不判定通过。
- 每轮只保留 `latest`，单场景失败不阻断其他场景。

## 验证结论

仓库静态检查、行为场景和 Benchmark 脚手架已建立。它们验证结构和决策边界，不代表真实 Figma Provider、外部业务项目或最终视觉还原已经完成验收。
