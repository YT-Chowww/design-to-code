# 验证方案

当前验证聚焦轻量单 Skill 的结构、决策和真实项目结果，不使用固定视觉分数代替人工判断。

## 1. 仓库静态检查

```bash
npm test
npm run check:d2c-skill
```

检查内容包括：主 Skill 与四个 Reference、项目规则模板、链接有效性、模板中立性、旧入口清理、当前文档表述、框架范围、Provider 行为场景和 Code Connect 边界。

`scripts/check-validation-suite.mjs` 是旧入口兼容器，只提示旧验证样本已归档并转到当前轻量检查。`docs/validation-fixtures/` 保留为历史样本，不作为当前能力通过证据。

## 2. 行为验证

使用 [行为场景](skill-evals/d2c-scenarios.md) 在新上下文中验证模型是否遵守关键决策：

- 缺少 `node-id` 时不猜节点、不写代码。
- Provider 自动选择覆盖“两者都有、仅官方、仅 Context、两者都没有”。
- 显式 Provider 不可用或认证失败时停止，不自动切换。
- 缺少 `D2C.md` 时先确认项目规则，再单独确认实现预览。
- 用户调整与 Figma 冲突时重新读取证据，并以用户最新要求为准。
- 公共组件、全局 Token、字体和资源的影响或缺失必须提前说明。
- 视觉偏差先由多模态模型或用户确认，再按需使用 Chrome；Chrome 不可用时明确未验证范围。

自动检查只验证场景是否完整登记。模型行为是否满足预期，必须保存真实前向评估结果，不能由静态检查伪造。

## 3. 真实项目验收

真实验收至少覆盖首版两类项目：

- React + TypeScript 项目。
- Vue 3 + TypeScript 项目。

每次记录实际 Provider、Figma 节点、目标项目与路由、修改文件、工程命令及结果、视觉证据、已知差异和未验证项。外部项目、登录、数据或 Provider 条件不足时标记为 `PENDING_EXTERNAL_INPUT`，不宣称完成。

## 4. 视觉复核边界

在 Figma Frame 对应视口打开目标项目真实页面：支持读取图片时由模型对照；不支持时并排提供 Figma 参考与真实页面，由用户指出偏差。只有存在具体偏差才检查相关元素的尺寸、盒模型、计算样式和父级布局。

修正必须落到项目源码；允许一次修正和一次复查。页面打不开、Chrome 不可用或用户尚未给出偏差位置时，交付中明确写“未验证”，不得把跳过描述为通过。
