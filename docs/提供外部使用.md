# 提供外部使用

日常使用以 `d2c` Skill 为主：它负责从具体 Figma 节点到现有 Web 前端项目的完整轻量流程；项目规则由各业务项目根目录的 `D2C.md` 单独维护。`d2c-benchmark` 是可选的第二个 Skill，只用于在四个固定场景中并排预览当前模型的生成结果，不合入业务项目，也不评分。

## 推荐安装方式

在本仓库根目录运行对应同步脚本：

```bash
bash scripts/sync-codex-skills.sh
bash scripts/sync-claude-skills.sh
```

`skills/` 是跨 Agent 共用的唯一 Skill 源。OpenClaw 等支持工作区 Agent Skills 的工具可直接发现此目录；Claude Code 和 Codex 使用上面的脚本，以符号链接同步 `d2c` 和可选的 `d2c-benchmark`。脚本不会复制项目配置或认证信息。同步后重启对应工具，再使用日常入口：

```text
/d2c https://www.figma.com/design/file-key/name?node-id=1-2 [target-directory]
```

需要可选基准预览时使用：

```text
/d2c-benchmark
```

## 安全同步行为

- 已有目标是本仓库同一 Skill 链接时，刷新链接。
- 已有目标是普通文件或目录时，保留并跳过。
- 已有目标链接指向其他来源时，保留并跳过。
- 对六个已退役名称，只删除目标确实指向本仓库对应旧路径的符号链接；不删除普通文件、目录或其他来源链接。
- Claude 同步不再分发全局编码/工作流规则；只清理本仓库管理的两个旧规则链接。项目规则以各项目独立确认的 `D2C.md` 为准。
- 同步脚本不安装、启动或认证 Figma MCP，也不读取、保存、复制或输出 OAuth、Token 等凭据。

## Provider 前提

Figma Provider 由使用者在运行工具中独立安装并完成认证。D2C 只依据当前会话里真实可调用的工具判断能力；不要把认证值写入本仓库、项目规则或对话。

在 Claude Code 中使用社区方案时，复制 `.mcp.example.json` 为本地 `.mcp.json`，并把 `--figma-api-key=<YOUR_FIGMA_API_KEY>` 替换为新生成的 Personal Access Token。Claude 会直接用该参数启动 `figma-developer-mcp`。本地 `.mcp.json` 已被 Git 忽略，不得提交或分享；仓库模板不保存真实 Token。

已有克隆从旧版本升级时，先在仓库外保存原 `.mcp.json` 的本地配置，确认备份后把仓库内该文件恢复为当前提交的版本，再拉取更新。更新完成后基于 `.mcp.example.json` 重建本地 `.mcp.json`，使用新生成的 Token，不要把备份加入 Git。

如另行安装官方 Figma MCP，两者都可用且用户未指定时默认官方；显式选择的 Provider 不可用或认证失败时停止，不自动切换。

## 已安装版本边界

仓库检查通过只证明仓库内 Skill 内容有效，不证明用户级已安装版本已经刷新。同步完成并重启工具后，应在新会话中确认加载路径和版本，再执行只读行为检查；未完成这一步时，将安装状态标记为未验证。

本仓库的工作树本地前向评估也不能替代已安装版本、真实 Provider 或业务项目验收。对应证据必须分别记录。

## 手动安装

无法使用符号链接时，把 `skills/d2c/` 复制到工具支持的 Skill 目录；需要基准预览时，再独立复制 `skills/d2c-benchmark/`。手动副本不会随仓库更新，升级后需要重新复制并再次验证已安装版本。

不要复制 MCP 配置、环境文件或其他项目级文件。目标业务项目的 `D2C.md` 由首次运行时分析并经用户确认后创建，不由安装包预置。
