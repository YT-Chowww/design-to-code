# 提供外部使用

## 当前推荐方式：同步 skills

在本仓库运行：

```bash
bash scripts/sync-claude-skills.sh
bash scripts/sync-codex-skills.sh
```

脚本会把 `.claude/skills/d2c*` 以 symlink 方式同步到本机 Claude 或 Codex skills 目录。重启对应工具后即可在任意项目中使用：

```text
/d2c-init
/d2c <figma-url> [target-directory]
```

## 手动复制方式

在业务项目根目录执行：

```bash
mkdir -p .claude/skills
cp -r /path/to/design-to-code/.claude/skills/d2c* .claude/skills/
```

初始化后会在业务项目里创建 `.d2c/`，其中 `.d2c/context/*.json` 是机器读取主数据，`.md` 文件是人工说明镜像。

## Plugin 化设想

如果后续要打包为 plugin，目录可以整理为：

```text
design-to-code-plugin/
├── .claude-plugin/
│   └── plugin.json
├── skills/
│   ├── d2c/SKILL.md
│   ├── d2c-init/SKILL.md
│   ├── d2c-extract/SKILL.md
│   ├── d2c-generate/SKILL.md
│   ├── d2c-validate/SKILL.md
│   ├── d2c-verify/SKILL.md
│   └── d2c-merge/SKILL.md
├── .mcp.json
├── settings.json
├── templates/
├── context/
└── scripts/
```

示例 `plugin.json`：

```json
{
  "name": "d2c",
  "description": "Design-to-Code: Convert Figma designs to Vue 3 or React code with artifact-driven validation and visual verification",
  "version": "1.0.0",
  "author": {
    "name": "your-name"
  },
  "license": "MIT"
}
```

## 注意事项

- Figma API Key 仍需要用户配置，推荐通过环境变量或本地 MCP 配置提供。
- `.d2c/context/` 是项目级数据，不应由插件覆盖用户已有配置。
- Skill 中的模板路径应使用 skill 相对路径解析，避免安装到缓存目录后失效。
- 运行工件统一写入目标项目 `.d2c/docs/`，不写入插件目录。
