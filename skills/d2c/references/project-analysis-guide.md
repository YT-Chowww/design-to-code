# 项目分析指南

## 原则

只读取足以决定当前实现的项目证据。先用文件名和入口定位范围，再打开少量相关文件；不做全库扫描。区分可长期写入项目根目录 `D2C.md` 的稳定规则与只属于本页面的现场事实。

## 有界取证顺序

1. **项目说明**：读取根目录的 agent/开发说明、已有 `D2C.md`、README 中与技术栈和验证有关的部分。记录明确规则及其来源。
2. **包与构建配置**：读取 package manifest、lockfile 类型、构建/框架配置和路径别名入口，确认框架、语言、包管理器、开发/检查命令；不要安装或升级依赖。
3. **TypeScript 配置**：读取根配置和目标目录实际继承的配置，确认 JSX、路径、严格性及构建引用。只在任务使用 TypeScript 时检查相关分支。
4. **组件、主题与样式入口**：定位组件库接入、项目公共组件目录、主题对象、CSS Variables、Less/Sass、utility theme 或全局样式入口。只展开与目标组件和设计值相关的定义和调用方。
5. **相似页面**：选择一到两个在页面类型、布局或交互上最接近的现有页面，学习目录组织、组合方式、数据状态、样式隔离和测试模式；不要把相似实现当成无需核对的模板。
6. **任务相关入口**：只检查目标页面需要的路由、数据来源、API 类型、状态管理、权限/埋点调用和验证命令。未知业务契约保持未知并询问用户，不从视觉稿补造。

每项结论保留证据文件或命令。稳定规则可以进入 `D2C.md` 候选；页面路径、临时兼容、API、路由、权限和埋点只进入本次实现预览。

## 组件分类

对每个候选组件标明分类、证据、调用方和变更影响：

| 分类 | 识别证据 | 实现边界 |
|---|---|---|
| 三方组件 | 来自依赖包或组件库公开入口 | 不改依赖源码；使用公开属性、主题、作用域样式或项目包装 |
| 项目封装公共组件 | 项目公共目录或统一导出，被多个页面复用 | 列出相关调用方和影响；公共修改需明确确认，优先兼容新属性且不改默认行为 |
| 页面局部组件 | 仅由目标页面或同一局部功能使用 | 可在已确认的任务范围内调整 |

不能仅凭文件名分类；用导入关系和调用方佐证。即使最终选择页面局部适配，也要说明避免公共修改带来的影响。

## Token 与样式作用范围

从宽到窄识别来源和影响：

```text
三方库主题 → 项目全局主题 → 公共组件 → 页面或局部组件
```

- 检查 CSS Variables、Less/Sass 变量、JS/TS 主题对象、组件库 Token、utility theme 和项目自定义变量中的相关值。
- 对每个候选映射记录 Figma 值、项目现值、来源文件、匹配依据、候选修改和作用范围。
- 优先复用可靠匹配；不匹配时优先页面局部适配。不得为了单页自动修改全局主题或公共 Token。
- 如果公共或全局改动确有必要，先列出调用方、影响和兼容方案，放入实现预览等待明确确认。
- 找不到可靠映射时，把 Figma 原始值限制在当前页面，并标记为页面局部值。

## 资源、业务与验证证据

- 定位项目既有字体声明、图片/图标目录、资源导入模式和许可说明；缺失项只报告，不静默替代。
- 记录必须保留的数据流、加载/空/错状态、表单语义、键盘/焦点、禁用态和错误提示。
- 验证命令按 `D2C.md`、package scripts/项目说明、询问用户的顺序确定，只选择覆盖 changed surface 的类型、Lint、测试、构建和真实路由启动方式。
- 输出未知项及需要用户决定的内容；缺少证据不是扩大扫描范围或猜测的理由。
